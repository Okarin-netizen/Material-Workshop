# マテリアル工房

中学1年 技術分野「材料と加工の技術」の学習用ブラウザゲームです。
依頼人の依頼にこたえて、部品ごとに **材料 → 加工方法 → 丈夫にする工夫** を選び、テストで確かめます。
正解は1つではありません。必要なテストにすべて合格すれば「依頼達成」です。性質の折り合いがよい設計ほど得点が高くなります。

- HTML / CSS / JavaScript（ES モジュール）だけで動きます。外部ライブラリ・外部フォント・画像ファイル・通信はありません。
- ビルドは不要です。フォルダをそのまま静的ホスティング（GitHub Pages など）に置けば動きます。
- 進み具合と図鑑はブラウザ（localStorage）に自動で保存されます。**名前は保存しません。**

## 遊び方

1. タイトルで「はじめる」（続きは「つづきから」）。
2. 依頼ボードで依頼を選ぶ。ランクは 見習い（依頼1〜3）→ 職人（4〜6）→ 名人（7〜8）。前のランクの依頼を2つ達成すると次のランクが開きます。
3. 5つのステップで設計します。
   1. 依頼を読む
   2. 材料を選ぶ
   3. 加工方法を選ぶ（その材料に合わない加工は灰色になり、理由が出ます）
   4. 丈夫にする工夫を選ぶ（選ばなくてもよい）
   5. テストと結果（合否と理由・教科書のページ、5つの指標のレーダーチャート、100点満点の得点）
4. 星の数：すべてのテストに合格で★1、さらに 70点以上で★2、85点以上で★3。
5. 「まとめ」画面で、達成した依頼・選んだ理由・ふり返りを A4 1枚に印刷（PDF 保存）できます。年・組・番・名前はこの画面で入力し、保存されません。

ヘッダーの「ふりがな」で、ふりがなの表示を切りかえられます（はじめは表示。設定は保存されます）。
先生用に、依頼ボードの下に「すべての依頼を開く」スイッチと「最初からやり直す」があります。

> 値段・特性・得点は **ゲーム用の目安** です（遊び方の画面にも書いてあります）。密度などの数値は教科書の値を使っています。

## ファイル構成

```
index.html                 入口。CSS と js/main.js を読みこむだけ
package.json               "type": "module" と、テスト用のスクリプト
css/
  base.css                 色・文字の大きさなどの共通の値、ふりがな、フォーカスの枠
  layout.css               ヘッダーと3列の配置、画面の大きさごとの切りかえ
  components.css           ボタン・カード・メーター・ステップ表示・ダイアログなどの部品
  screens.css              画面ごとの見た目（設計台・結果・依頼ボード・図鑑・まとめ など）
  print.css                まとめ画面の印刷用（A4 1枚）
js/
  main.js                  起動。データの点検、画面の切りかえ、保存、フォーカスの復元
  data/                    ── 表示する文章と数値はすべてここ ──
    traits.js              特性（強さ・軽さ…）、製品の指標（5つ）、材料の種類
    materials.js           材料（13種類）。特性・値段・教科書のページ・見た目
    processes.js           加工方法（8種類）。向いている材料の種類と、向かない理由
    reinforcements.js      丈夫にする工夫（三角形の構造・面構造・焼き入れ など）
    requests.js            依頼（8件）。部品・テスト・得点の重み・コメント・学びのポイント
    uiText.js              画面に出るその他の文章（ボタン名・説明など）
  core/                    ── DOM を使わない純粋な処理（node --test で確かめられる） ──
    constants.js           星の基準点や文字数の上限などの決まった数
    rubyParse.js           {漢字|かんじ} の書き方を読みとる
    rules.js               選べる加工・工夫の判定、設計の整理
    scoring.js             設計の評価（特性 → テストの合否 → 指標 → 得点 → 星）
    gameState.js           進み具合の変更（材料を選ぶ、テストする など）
    storage.js             localStorage への保存と読みこみ
    validateData.js        データの参照ミスを起動時に点検する
  ui/
    dom.js                 要素を作る小さな関数 h() / s()（文字列は自動でふりがな付きになる）
    components/            ヘッダー、ステップ表示、カード、メーター、レーダーチャート など
    art/                   製品の絵（インライン SVG）。依頼ごとの描き方
    screens/               画面（タイトル・遊び方・依頼ボード・設計・結果・図鑑・まとめ）
      steps/               設計の各ステップ（読む・材料・加工・工夫）
tests/
  *.test.mjs               node --test で動く単体テスト
  fixtures/answers.mjs     依頼ごとの模範解・よくある誤答・おしい答え
  e2e/playthrough.e2e.cjs  Playwright で依頼1〜8をクリックで通す確認
```

## ふりがなの書き方

画面に出る文字列はすべて `{漢字|かんじ}` の形でふりがなを書きます。表示のときに `<ruby>` になります。
`*強調*` と書くと太字の強調になります。`{budget}` のように `|` のない波かっこは、数値を入れる場所です。

## 依頼や材料を追加するには

### 依頼を追加する

1. `js/data/requests.js` の依頼1（公園のベンチ）をまるごとコピーします。依頼1には各項目の意味をくわしくコメントで書いてあります。
2. `id`・依頼人・部品（使える材料と加工方法）・テスト・得点の重み（合計100）などを書きかえます。
3. 製品の絵を `js/ui/art/` に追加し、`js/ui/art/index.js` の一覧に依頼の `id` で登録します。
4. `tests/fixtures/answers.mjs` に模範解（★3）・誤答（不合格になるテスト）・おしい答え（★1〜2）を追加し、`node --test` で確かめます。

### 材料・加工方法・工夫を追加する

`js/data/materials.js`・`processes.js`・`reinforcements.js` に、同じ形で1つ追加します。
依頼で使うときは、`requests.js` の部品の `materialIds` / `processIds`、または依頼の `reinforcements` に `id` を書きます。

### データのまちがいに気づくしくみ

起動時に `validateData` が、存在しない `id` の参照・得点の重みの合計・ふりがなの書き方などを点検します。
問題があれば、ブラウザのコンソールと画面上部の赤い帯に内容が出ます。

## 手元で確かめる

```sh
# 画面を開く（ES モジュールなので file:// ではなくサーバーが必要）
python3 -m http.server 8000
# → ブラウザで http://localhost:8000/ を開く

# 単体テスト（Node.js 18 以上）
node --test

# E2E（Playwright が入っている環境で。スクリーンショットの保存先を指定できる）
node tests/e2e/playthrough.e2e.cjs ../material-koubou-shots
```

## GitHub Pages で公開する

1. このフォルダの中身を GitHub のリポジトリに置きます（`index.html` がいちばん上にくるように）。
2. リポジトリの **Settings → Pages** で、Source を「Deploy from a branch」、Branch を `main`・フォルダを `/ (root)` にして保存します。
3. 数分後に表示される URL（`https://<ユーザー名>.github.io/<リポジトリ名>/`）を開きます。

パスはすべて相対パスなので、リポジトリ名がどこに入っても動きます。

## 補足

- まとめ画面には、依頼ごとに「最後に合格した設計」とその星を載せます（依頼ボードの星は、それまでの最高）。
- 保存はブラウザごと・端末ごとです。別の Chromebook やシークレットウィンドウでは引き継がれません。
- 音は出ません。
